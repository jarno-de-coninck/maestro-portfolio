## 3.2 Usability 

Usability is the degree to which a software system or interface allows users to achieve their goals effectively, efficiently, and with satisfaction, meaning it is easy to learn, quick to use, minimises errors, supports recovery when mistakes occur, and provides a smooth, intuitive experience through well-designed UI and UX. 

## **Assignment** 

Create a complete functional design for your application by means of a wireflow. Your functional design must make use of three guidelines of the Nielsen’s Usability Heuristics with substantiation: 

1. Heuristic 1: Visibility of System Status 

2. Heuristic 5: Error Prevention 

3. Heuristic 9: Help Users Recognize, Diagnose, and Recover from Errors 

Your project must include the complete wireflow (with correct wireframes), including the motivation for each of your chosen usability guidelines. The subsequent implementation must match the submitted wireflow. The fidelity of the wireframes must be high enough to justify and substantiate Nielsen's Heuristics (for example, the wireframe should have colour so that you can discuss errors).

## 3.5 DevOps 

Not so long ago, life as a software engineer was relatively simple: developers built software and handed it over to the Operations department, who were responsible for running it, often leading to blame when things went wrong. Over time, it became clear that this approach was ineffective, and modern development now follows the principle of _“You build it, you run it,”_ where teams take responsibility for both development and operation. This approach, known as DevOps (a combination of Development and Operations), emphasises shared ownership and reliability, and highlights the importance of creating consistent development environments to avoid issues when deploying applications or collaborating across different systems. 

## 3.5.1 Containers: Local Environment 

In this assignment, we use Docker to containerise our application. The assignment is to create a Docker environment that contains a web server with PHP, dependency management tooling, as well as volumes to fully host your application. Your project must provide instructions on the use of the Docker environment in the README.MD file in your Git repository for each of the steps below. 

1. The first step is to create a single container that can be started and stopped using manual Docker commands like `docker build` and `docker run` and hosts both the webserver and SQLite database. The application data is stored using Docker volumes. The initial database migration should be included as a separate command. 

2. The second step is to add Docker compose. Using Docker compose your container from step 1 should be able to start using a single command. 

3. The third step is to separate the database into a separate container that hosts a relational database server like MySQL or PostgreSQL. The webserver and database server containers communicate with each other over a Docker network. Note, to achieve this, you must utilise the repository pattern in the framework to also work with the database server of your choosing. 

## 3.5.2 Deployment (a.k.a. Production) 

There is no use in developing an application if you can’t deploy it live for everyone to use. For this assignment, you take three steps. Each step is a prerequisite before you can go to the next step. In other words, you can’t set up the CI-check before enhancing the readme file. 

1. Deploy your application remotely to be fully functional and accessible from anywhere on the internet using a domain name over HTTPS. You may make use of shared hosting platforms, VPS hosting or PaaS hosting. 

2. Your project readme must include full instructions on how to set up and release new versions of your application on your selected production environment. 

3. To ensure quality before each deployment your application includes several continuous integration (CI) checks that run on GitHub after each push to the main branch: 

   - a. PHPStan should report no issues on level 8 

   - b. PHPCS should report no issues against the PSR-12 standard 

   - c. Deptrac should report no dependency issues 

If any of these checks fail the CI step fails and the developer is informed. 

## 3.6 Client-Side APIs 

Client-side APIs enable front-end applications to communicate with external services and backend systems, allowing dynamic data exchange and interaction beyond the browser itself. Using fetch(), you can send requests, receive structured data like JSON, and update the user interface in real time. 

## **Assignment** 

- Create a simple RESTful API of your choice, including at least three endpoints with clear request/response formats in JSON. 

- Build the API into the backend of your application. 

- Develop a front-end page that uses JavaScript/TypeScript **fetch()** to communicate with your API, displaying retrieved data dynamically.
